## Context

The dataset map currently renders in a two-column card: the Leaflet map receives the flexible column and a fixed 19rem search/summary aside consumes the other. Country fills encode relative matching-record counts, while selection replaces the normal white 0.8px stroke with a near-black 2.5px stroke. At world zoom that selected stroke dominates small and medium polygons and can be confused with the darkest count fill.

The map already aggregates the canonical filtered rows in memory and retains each named record's row ID. The table uses the same in-memory row cache and TanStack table state, but it has no transient map scope or record-detail interaction. The shared DataGrid already supports row-click callbacks, and the application already uses shadcn/Base UI sheets for read-only and editable detail surfaces.

## Goals / Non-Goals

**Goals:**

- Give the geography the full card width and separate search, map, and record results into a clear vertical hierarchy.
- Make count intensity and selection visually distinct at all supported zooms.
- Carry a selected country or record subset into the existing table without creating or saving new data.
- Provide one consistent read-only record profile from either the map result panel or a table row.
- Preserve keyboard access, responsive behavior, provider-free runtime requests, and current filter semantics.

**Non-Goals:**

- Create a canonical cross-dataset People Group entity page or a new URL route.
- Persist map record selections in saved views, datasets, downloads generated by the server, or browser storage.
- Add bulk mutation, record editing, geocoding, third-party tiles, database schema, auth, or permission changes.

## Decisions

### Decision: Use a vertical map composition

Search becomes a compact toolbar above a full-width map. The matching-record legend remains directly below the map, and the selected-country record panel follows it in normal document flow. This improves the geography at desktop widths and naturally stacks on mobile without an alternate layout.

The rejected alternative was a collapsible right sidebar. It preserves more map width only when collapsed, adds another stateful control, and still makes the primary interaction dependent on viewport width.

### Decision: Separate count encoding from selection encoding

Country fill and fill opacity remain functions of matching-record count only. Selection uses a thinner brand-aligned stroke and brings the selected layer forward; it does not darken the fill. Keyboard focus remains available through the existing accessible SVG paths.

The rejected alternative was changing the selected fill. That would make the legend inaccurate and continue conflating selection with intensity.

### Decision: Keep map-to-table scope transient and parent-owned

`DatasetDetailClient` owns an optional temporary scope containing a label and row-ID set. `DatasetMapView` emits a requested scope and the parent switches to Table mode. `useDatasetTableState` continues to expose the canonical filtered rows for map aggregation while building the TanStack table from the temporary subset when present. A visible table banner clears the scope.

This scope is deliberately excluded from saved filter state and URL state. Client-side download follows the displayed table rows; saved views and dataset assignments continue to describe the canonical filter configuration and visibly do not claim to persist the temporary selection.

The rejected alternative was translating map selection into the existing Country filter. That cannot represent arbitrary multi-record selections and would mutate the user's durable filter state.

### Decision: Add complete record summaries to map aggregation

Each mapped country aggregate retains a stable record summary for every mapped source row, including a fallback label for rows without a people-group name. This guarantees that `View all` and selection counts match the country aggregate rather than relying on the existing named-people-group search subset.

### Decision: Use a reusable read-only sheet for one record

A dashboard-level `DatasetRecordProfileSheet` displays the selected row using the dataset's currently visible columns and established display-label/value formatting. Map record buttons and table row clicks both open the same sheet. The sheet is a record inspection surface, not a new canonical profile route.

### Decision: Bound long country lists without hiding records

The record panel uses a fixed-height scroll region and renders records in progressive batches. `View all in Table` always includes the complete country row-ID set, while `Show more` expands the selectable list. This avoids placing thousands of controls in the DOM for large source datasets.

## Risks / Trade-offs

- [Temporary table scope can be mistaken for a saved filter] → Show a prominent scope banner with the scoped count, source label, `Clear` action, and copy that it is temporary.
- [Rows without a people-group label are hard to recognize] → Use a deterministic `Record <source row number>` fallback while preserving the stable row ID internally.
- [A selected stroke can still dominate very small polygons] → Use a thinner stroke than today and test representative large and small polygons at world and focused zooms.
- [Rendering a large selected-country list can affect responsiveness] → Use progressive batches inside a bounded scroll region and keep bulk table handoff independent of rendered batch size.
- [Table row clicks could interfere with future row controls] → Keep the callback at the DataGrid row level and ensure interactive child controls stop propagation if later introduced.

## Migration Plan

No data migration or remote provider change is required. Deploy through the existing Git/PR workflow after the local change gate passes. Rollback is a normal application commit revert; source rows, saved filters, and bundled ISO3 geometry are unaffected.

## Open Questions

None. The lightweight MVP defines “profile” as a read-only record sheet; a canonical entity page remains future scope.

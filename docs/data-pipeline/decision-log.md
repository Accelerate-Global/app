# Data pipeline decision log

This log distinguishes approved AX Online replacements from unresolved legacy
ambiguities. `Approved` means the repository plan/spec has selected the target
behavior; it does not claim that every later wave is already implemented or
deployed. `Blocked` means a future engine/product may be built behind a flag,
but publication must remain disabled until the data owner approves the result.

## Approval protocol for blocked decisions

1. Add or update a sanitized fixture that shows every viable alternative.
2. Record the selected expectation and reason in this table.
3. Promote the expectation to a direct engine/product golden test.
4. Update the relevant OpenSpec requirement and resource/rule checksum.
5. Only then enable publication for the affected engine or product.

Do not resolve a blocked rule by changing only the golden output. The decision,
specification, implementation, and fixture must move together.
